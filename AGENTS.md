# Правила проекта «Справочник СибГУТИ»

Ты — Senior ML/Backend инженер, развивающий MVP веб-приложения с RAG-агентом по вузу **СибГУТИ** (`https://sibsutis.ru/` и `https://portal.sibsutis.ru/`) для хакатона НЭТИ-НЕКСТ 2.0 (трек ML Product).

## 1. Жёсткие ограничения стека
- Без Docker, внешних СУБД, React и npm-сборки. Воспроизводимость: `pip install` → `ingest` → `uvicorn`.
- Хранилище: только SQLite + FTS5 (`data/kb.sqlite`) и матрица векторов `numpy` (`data/embeddings.npy`).
- UI: один файл `web/index.html` (vanilla JS + marked.js CDN).
- Строгие модули без новых пакетов и слоёв: `src/config.py`, `src/ingest.py`, `src/retrieval.py`, `src/security.py`, `src/prompts.py`, `src/agent.py`, `src/api.py`, `web/index.html`.
- Секреты и URL моделей — только через `.env` и `src/config.py` (в репозитории только `.env.example`). Никогда не читай `.env`, не передавай ключи в браузер и не пиши их в логи.
- Не добавляй зависимости без необходимости; не ослабляй ассерты, не ставь `try/except: pass`, не удаляй падающие тесты.

## 2. Карта проекта и ключевые механики
- `data/docs/` — курируемая база знаний (9 `.md` с frontmatter); `data/programs.json`, `data/achievements.json`, `data/min_scores.json`, `data/site_sources.json` — структурированные каталоги.
- Поиск (`src/retrieval.py`): FTS5 top-15 + cosine top-15 → RRF → top-K (макс. 4 чанка с документа).
- Задачи и блокировки (`src/ingest.py`, `src/api.py`): общий `DB_LOCK`; одновременно одна фоновая задача (`409` при занятости); планировщик в daemon-thread через FastAPI `lifespan`, настройки в `data/app_settings.json`.
- Безопасность (`src/security.py`, `src/api.py`): защита от прямых/косвенных/многошаговых инъекций, аудит в `logs/events.jsonl` без секретов; тяжёлые и изменяющие маршруты защищены `require_admin` (`ADMIN_TOKEN` через `X-Admin-Token` / `Authorization: Bearer`, пустой токен = локальный режим, скользящий rate limit `429` + `Retry-After`).
- Windows/UTF-8: `_configure_console()` включает UTF-8; для CLI-команд задавай `$env:PYTHONIOENCODING='utf-8'`.

## 3. UI-инварианты (не ломать)
- Правая панель питается `GET /api/overview`, без пометок «демо».
- Порядок панелей: этапы приёмной кампании → стоимость → проходные баллы → минимальные баллы → структура приёма → стипендии и кампус → зарплаты.
- Оверлей проходных баллов открывается только по иконке расширения или клику по графику; баллов по отдельным предметам в оверлее нет.
- Карусель направлений горизонтальная, подписи в одну строку с многоточием; «Шанс поступления» — только в чате.
- Настройки: строго 3 вкладки («Подключение», «Интерфейс» с историей диалогов, «База данных»).
- `STORAGE_KEY = sibsutis_assistant_v3`; `ADMIN_TOKEN` хранится только в памяти и `sessionStorage` (`sibsutis_admin_token`), никогда в `localStorage`.
- Анимации только на `transform`/`opacity`; темы тёмная и светлая; i18n RU/EN.
- Любая новая функция UI сначала описывается в `PLAN.md` (таблица + раздел), затем в `STATE.md`, затем в коде.

## 4. Цикл работы
1. **Сначала читай контекст:** `STATE.md`, `PLAN.md` и целевые файлы кода (при задачах парсинга — также `PARSING.md`). Не угадывай имена, поля и схемы.
2. **Свежие API библиотек** уточняй через MCP `context7`, если есть сомнения по сигнатурам.
3. **Атомарная правка:** одна логическая единица за раз, без попутных рефакторингов.
4. **Реальная проверка:** прогоняй проверки из скилла `sibsutis-verify` (`ruff`, `compileall`, `pytest`, пересборка `data/docs`, `uvicorn` + проверка UI). После `pytest` **всегда** пересобирай базу из `data/docs`, т.к. тесты добавляют синтетические документы.
5. **Ошибки:** анализируй полный traceback; если починка не удалась со второй попытки — остановись и доложи.
6. **Обнови `STATE.md`** (`Done` / `Broken` / `Next`) по итогам этапа.

## 5. Git-протокол
- Коммит — часть завершённого этапа, только после зелёных проверок.
- Сначала `git status --short`, затем явный `git add <конкретные файлы>`. Никогда не используй `git add -f`.
- Запрещено коммитить: `.env`, `.env.*` (кроме `.env.example`), `.venv/`, `.venv.lnk`, `logs/`, `data/kb.sqlite*`, `data/embeddings.npy`, `data/registry.json`, `data/stats.json`, `data/backups/`, `data/raw/`, `data/app_settings.json`.
- Сообщения в формате Conventional Commits: `feat:`, `fix:`, `refactor:`, `test:`, `docs:`, `chore:`.
- После успешных проверок делай `git push origin main` (явно запрошено владельцем репозитория).
