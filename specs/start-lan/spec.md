# Спецификация: запуск агента по локальной сети (Wi-Fi)

## Проблема
`start.bat` привязывает сервер к `127.0.0.1`, поэтому страницу агента нельзя открыть
с другого компьютера (например, с машины для выступления) по ссылке вида
`http://<IP>:8000/`.

## Предлагаемое решение
Добавить `start-lan.bat`, который:
- запускает существующий `start.bat` с `HOST=0.0.0.0` (слушать все интерфейсы);
- определяет локальный IPv4-адрес машины и печатает готовую ссылку;
- открывает браузер уже по сетевому адресу;
- напоминает про брандмауэр и `ADMIN_TOKEN`.

Логика установки зависимостей и сборки базы остаётся в `start.bat` — без дублирования.

## Границы
### Входит
- `start-lan.bat` и минимальная правка `start.bat` (переопределяемый `HOST`, вывод LAN-ссылки).
- Проверка, что сервер слушает `0.0.0.0` и отвечает по LAN-IP.
- Раздел в `README.md`.

### Не входит
- Автоматическое создание правила брандмауэра (требует прав администратора).
- HTTPS, авторизация пользователей, туннелирование через интернет.
- Изменения API, UI и схемы базы.

## Критерии успеха
- `start-lan.bat` с нуля (без запущенного сервера) поднимает приложение и печатает
  ссылку `http://<LAN-IP>:8000/`.
- `Get-NetTCPConnection -LocalPort 8000` показывает прослушивание на `0.0.0.0`.
- `GET http://<LAN-IP>:8000/api/health` возвращает `ok`.
- `start.bat` по-прежнему работает в локальном режиме `127.0.0.1`.
