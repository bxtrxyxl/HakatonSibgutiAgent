# План: публичная ссылка на приложение через ngrok

## Архитектура и поток данных
1. `start-public.bat` читает настройки из `.env` (только `NGROK_AUTHTOKEN`, без
   вывода значения на экран) и проверяет `ngrok.exe config check`.
2. Если authtoken нет — однократный ввод и `ngrok.exe config add-authtoken`;
   токен сохраняется в `%LOCALAPPDATA%\ngrok\ngrok.yml`, не в проекте.
3. Приложение поднимается тем же `start.bat` (тот же `.venv`, та же сборка базы),
   поэтому поведение не отличается от обычного запуска.
4. `ngrok http 8000 --log=stdout` открывает исходящий туннель до
   `127.0.0.1:8000`; публичный URL берётся из локального API агента
   `GET http://127.0.0.1:4040/api/tunnels` (фильтр по `config.addr` = `:8000`).
5. Браузер открывает `https://<random>.ngrok-free.app/`. Страница и API находятся
   на одном origin, поэтому `resolveApiBase()` из `web/index.html` отправляет
   `/api/chat`, `/api/overview`, `/api/databases` в тот же туннель — правки UI не
   нужны.

## Изменения API
Нет. Туннель прозрачен для FastAPI; CORS не требуется, так как запросы
same-origin.

## Изменения UI
Нет.

## Риски и допущения
- Бесплатный ngrok показывает промежуточную страницу-предупреждение при первом
  заходе в браузере (нужно нажать «Visit Site»). Это ограничение тарифа.
- Бесплатный URL случайный и меняется при каждом перезапуске туннеля.
- Бесплатный тариф ограничивает число одновременных сессий агента; скрипт
  переиспользует уже открытый туннель на порт 8000, если он есть.
- Публичная ссылка = публичный чат: без `ADMIN_TOKEN` любой может вызвать
  пересборку/бэкапы, а чат расходует кредиты LLM-провайдера. Скрипт предупреждает.
- `ngrok.exe` не коммитится (бинарник 33 МБ) — в `.gitignore`; на новой машине
  его скачивают с https://ngrok.com/download.
- Антивирус/корпоративный прокси может блокировать исходящие соединения ngrok;
  тогда в логе будет `ERR_NGROK_*`, скрипт печатает последние строки лога.
