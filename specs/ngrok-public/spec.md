# Спецификация: публичная ссылка на приложение (Cloudflare + ngrok + SSH-туннель)

## Проблема
Приложение запускается локально на `http://127.0.0.1:8000` (или по LAN-IP внутри
одной Wi-Fi-сети). Для показа жюри или удалённому человеку нужен адрес в интернете.
Открывать порт наружу через брандмауэр и белый IP долго и небезопасно, а на
учебной/гостевой сети входящие соединения часто заблокированы.

Проверка на рабочей сети (`nstu-free`, IP 195.62.7.253) показала:
- ngrok отказывает в соединении: `ERR_NGROK_9040` («We do not allow agents to connect
  to ngrok from your IP address») — ограничение ngrok для части сетей, VPN и
  провайдеров, настройками проекта не лечится;
- SSH-туннель `localhost.run` выдаёт адрес, но TLS-соединение к нему сбрасывается;
- Cloudflare quick tunnel (`cloudflared`) работает: `https://<id>.trycloudflare.com`
  отдаёт страницу и API (200), но только с `--protocol http2` (QUIC-регистрация на
  этой сети не поднимается).

Кроме того, `start.bat` при запуске сам открывал локальную страницу, поэтому
пользователь видел `127.0.0.1:8000` вместо публичной ссылки.

## Предлагаемое решение
`start-public.bat` — один клик:
1. поднимает приложение через `start.bat` с `NO_BROWSER=1` (локальная страница не
   открывается) и ждёт `/api/health`;
2. открывает туннель Cloudflare: `cloudflared tunnel --url http://127.0.0.1:8000
   --protocol http2 --no-autoupdate`; если `cloudflared.exe` нет в корне проекта,
   скачивает его один раз (~55 МБ) с GitHub releases;
3. ждёт в логе `Registered tunnel connection`, берёт адрес
   `https://<id>.trycloudflare.com` и проверяет через него `/api/health`;
4. если Cloudflare не поднялся — пробует ngrok (authtoken из `NGROK_AUTHTOKEN` в
   `.env` или однократный ввод), затем бесплатный SSH-туннель
   `ssh -R 80:localhost:8000 nokey@localhost.run`;
5. печатает ссылку, открывает её в браузере, предупреждает о публичности (кредиты
   LLM, `ADMIN_TOKEN`) и по нажатию клавиши закрывает только свой туннель, оставляя
   сервер работать.

## Границы
### Входит
- `start-public.bat` с тремя транспортами (Cloudflare, ngrok, SSH), `NO_BROWSER` в
  `start.bat`, `NO_OPEN` для запуска без открытия браузера, `NGROK_AUTHTOKEN` в
  `.env.example`, правила в `.gitignore`, раздел в `README.md`, `STATE.md`, журнал
  `HANDOFF.md`.
- Повторный запуск переиспользует уже поднятый сервер.

### Не входит
- Платный домен, постоянный URL, OAuth на входе.
- Изменение API, схемы БД, логики поиска и UI-панелей.
- Проброс других портов и настройка брандмауэра (туннели работают исходящими
  соединениями).

## Критерии успеха
- `start-public.bat` печатает рабочую публичную ссылку и открывает именно её, а не
  `127.0.0.1:8000`.
- По публичной ссылке страница загружается, правая панель заполнена, вкладка
  «База данных» показывает активную базу, чат отвечает.
- Если Cloudflare недоступен, скрипт переходит к ngrok, затем к SSH-туннелю.
- Закрытие скрипта не оставляет висящих cloudflared/ngrok/ssh-процессов и не гасит
  сервер.
- `ruff`, `compileall`, `pytest` остаются зелёными (Python-код не меняется).
